## 瓶頸假說及與前次研究的連接

1. **輸入的可用性**：局部棋形的結果比許多擴資料／換表示探針強，但只證明目前學習流程可利用它，沒有證明原主幹不含這些資訊。
2. **條件配對**：現行 `pid_win2.py` 把自己落點與對手上一手的兩個 CNN 輸出相加，再交給 Transformer。Transformer 能學交互作用；不能稱它「看不到關係」。未知的是用整局身分損失是否足以學出細微的情境—選擇關係。
3. **跨局取證**：同樣的落點／形狀比例可能來自不同情境。應比較「遇到類似選擇時怎麼下」，不只比較整局平均像不像。

前次 reference-policy（協議 `7b991b270173`）已顯示參考棋可以改善個人選擇似然，但 attention 對另訓 uniform 的優勢未跨兩個種子穩定成立。其 key 使用全盤 trunk 平均＋value／entropy／ply／color，action/value 路徑則保留完整空間通道。新的假說是 **配對情境太粗**，不是「舊模型完全沒有局部資訊」。舊結果也可能受樣本量、最佳化或容量影響，不能先認定 key 是唯一原因。

## 選定的模型方向：局部條件選擇記憶

不再另開一輪單純加寬／加深序列模型；主線已有 CAP 對照。下一個專門模組以候選人的參考棋為記憶，直接預測在當前局面的選擇分布。

- **情境 key `k(s)`**：落子前的對手上一手附近棋形、輪到誰、手數，以及基礎 policy 對可選局部形狀的加權摘要。保留全盤摘要以免兩個局部相同、全局急迫性不同的局面被強行視為相同。
- **每個合法動作的表示 `h(s,a)`**：候選落點附近棋形、對手上一手附近棋形、兩者相對位移，以及它們的交互作用。不是只為實際落點做一個視窗；所有合法落點與 pass 都有分數。
- **參考決策 value**：`h(s_i,a_i) - E[a~p0(.|s_i)] h(s_i,a)`。這是在可選動作背景下的偏好殘差，並不宣稱扣除了全部棋力／開局影響。
- **個人記憶 `m_u(s)`**：先按情境在每盤參考棋內取證，再跨盤平均；保留 null 記憶，使沒有相近情境時可以退回基礎 policy。
- **輸出**：`p_u(a|s) ∝ p0(a|s) exp(2 tanh(m_u(s)ᵀ h(s,a)/sqrt(d)))`，在全部合法動作上重新正規化。整局得分使用觀察到的選擇之平均 log likelihood ratio，再評估跨局合併。

這能表達一種整局比例可能分不開的情況：甲乙整體都有一半近處回應、一半遠處落子，但甲在情境 X 常近回、Y 常遠走，乙相反。這是可測試的合成例子，不是已觀察到的真實玩家分類。

**防洩漏要點**：query 的實際落子不能參與情境 key、參考選取、或可選動作摘要；先形成全分布，再用實際落子評分。參考 value 可以使用該參考盤已發生的落子。所有局面來自落子前狀態；pass、首手無對手上一手、盤外標記要明確處理。棋盤重播沿用已驗證的提子規則，不把先前已試過的「補正提子」當新訊號。

特別注意：不可直接移植 `pid_win2.windows2()` 的 `pok = ok & (ppos < 361)` 到情境 key，因為 `ok` 取決於 query 實際落子是否 pass。新 key 的前手有效性只能依歷史判定。對固定狀態換成任何標記落子（包括 pass），key、檢索權重、完整預測分布都必須不變。

## 最小可辨別實驗

先做可逆的小型機制實驗，之後才做完整 baseline 的增益驗證。

| 臂 | 記憶選取 | 動作表示 | 要回答的問題 |
|---|---|---|---|
| U | uniform、跨參考局平均 | 局部交互作用 | 個人平均偏好能做到多少 |
| G | 舊全盤情境 key | 相同局部交互作用 | G 對 U 測全盤情境檢索的收益 |
| L | 全盤＋局部情境 key | 相同局部交互作用 | 更具體的情境配對是否勝過 G／U |
| A | 與 L 相同 | 兩個視窗的加性表示 | 顯式交互作用是否必要 |

共同使用相同資料、參考局、合法動作、訓練步數、checkpoint 選取規則與至少兩個種子。公開可訓練參數量／運算量，匹配 key／輸出維度；uniform 的有效參數不同，不稱它嚴格等容量對照。不論 L 增益多大，都必須有同參數量的 G 控制後才把差異歸因於局部 key。這四臂不單獨識別新 action 表示相對舊表示的收益；如要回答它，須同配方另訓舊 action 對照，不能拿前次不同測試集的分數相減。

訓練契約：沿用協議 `7b991b270173` manifest 記錄的 humanv0 checkpoint 作凍結 p0，啟動前驗證原路徑與 SHA256，寫入新 manifest。各臂分開訓練自己的 key／h／memory，使用同初始化種子與相同 episode 序列，不跨臂偷用最優 checkpoint。沿用 identity CE（以每盤平均選擇 log likelihood ×10 為 logit）＋0.1 真 owner move NLL；checkpoint 由共同開發集的三盤平均分數 CE＋0.1 move NLL 選取。新 manifest 必須記錄 p0 訓練資料的已知來源及其未知重疊；「未見玩家」只指 adapter 的玩家隔離，不能宣稱預訓練 p0 從未見過這些人。精確樣本數、步數與控制容量在資料／吞吐稽核後、任何新測試開封前固定。

- 合成測試：兩人選擇邊際完全相同、條件偏好相反；模型須在未見情境樣本區分，並通過零記憶、合法正規化、候選人重排、query-action 不影響 key 的測試。
- 真實測試：訓練／開發／測試的 adapter 玩家分開；跨資料集以實體棋局去重。先前已看過的測試玩家只能作開發證據；正式新測試名單須另選、凍結且一次開封。是否能選足夠新玩家要先稽核，不能預設已成立。
- 置換已算好的完整 reference residual value 與 context key 的配對，不直接交換原始落子，以免產生非法落子或改變 p0 難度。在 owner／參考局內、執色／手數等可比分層內置換，保留 key／value 各自邊際、參考局配置與記憶長度；另記每層可置換比例。此控制只支持「檢索時 key–value 配對有用」，不宣稱完全排除棋力／開局分布。檢查匹配密度與 null 權重；密度不足不是零訊號證據。
- 機制證據需同時看 L 對 G／U 的 owner-cluster 區間、條件配對置換、真 owner 對錯 owner 的選擇似然；不能只看下一手 loss 下降。開局、棋力與局長分層是描述性檢查，不事後挑最好的子群當主要結果。
- 單局與多局分開報告，並檢驗其增益差的區間；不能把「一個顯著、另一個不顯著」當成兩者顯著不同。
- 最後用當時已通過主線判定的完整模型固定候選排序／融合權重，再測新增模組。困難玩家只能從訓練／開發資料找，不能用測試真值挑出有利 shortlist。全體候選評分、救回／破壞題數、玩家分群區間都必須保留。
