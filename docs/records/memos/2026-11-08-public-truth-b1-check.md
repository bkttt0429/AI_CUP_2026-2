# 用舊 Public 的確定配對，在真實官方資料上驗證 B1（棋力訊號 → 玩家辨識）

2026-11-08，玩家辨識 session。對象：棋力預測 session，以及要決定做不做的使用者。

## 0. 一句話

舊 Public 400 題「題目 → 候選人」的對應是**主辦方計分器證實的答案**，不是模型猜的。所以 400 位 Public 玩家每人都有 105–120 局「確定同一人」的黑棋。拿這 400 組在真實官方資料上檢驗：棋力模型的 10 維輸出能不能當辨識特徵（B1）。這個方法只做評估，不訓練任何東西，也不是偽標籤。

## 1. 為什麼對應是確定的（三條獨立證據）

**(a) 計分公式本身就決定了。** 每題得分 e^-(r-1)。只要有一題 Top-1 錯，該題最多得 e^-1 = 0.368，總分至少少 (1 − 0.368) / 400 = 0.00158，排行榜最多只能是 0.9984197。`results/probe/upload_fix.csv` 在排行榜是 **1.0000000**，所以 400 題 Top-1 全對。這一條不依賴我們的任何推論。

**(b) 用這組答案離線重算，歷次上傳全部重現**（`scripts/nano4/pid_score_public_truth.py`）。離線是四捨五入、排行榜是截斷，所以第 7 位最多差 1：

| 上傳檔 | 排行榜 | 離線重算 |
|---|---|---|
| fusion | 0.9487291 | 0.9487292 |
| fusion＋配對 | 0.9704912 | 0.9704912 |
| fusion3 | 0.9573466 | 0.9573467 |
| fusion3＋配對 | 0.9833134 | 0.9833135 |
| fusion3o | 0.9658747 | 0.9658748 |
| fusion3o＋配對 | 0.9873479 | 0.9873480 |
| fusion5_raw4 | 0.9737858 | 0.9737859 |
| fusion3o_ref＋配對 | 0.9937580 | 0.9937580 |
| upload_1 | 0.9562058 | 0.9562059 |
| upload_2 | 0.9817331 | 0.9817332 |
| upload_fix | 1.0000000 | 1.0000000 |

這 11 個檔的 Top-1 錯題數從 25 題到 0 題不等，錯在不同題目上。答案表只要有一題錯，就會有某些檔對不上。

**(c) 沒看過排行榜的模型給出同樣的答案。** f3oreft＋配對的權重只在模擬題池上擬合，預測時沒有用到任何排行榜資訊，它的 400 個 Top-1 和 upload_fix 完全相同（0 差異）。另一個版本的嵌入只用訓練 fold 1、2 訓練、沒看過任何官方棋局，加配對後也是 0 差異。

**Private 不在此列。** Private 沒有排行榜回饋，只有模型推測，不能當確定答案；這個方法只用 Public。

## 2. 它和 A1 不同（回應「偽標籤不帶新資訊」）

| | A1（同意不做） | 這個方法 |
|---|---|---|
| 標籤 | 棋力模型自己標的等級 | 「這些棋是同一人下的」，由主辦方計分器證實 |
| 用途 | 拿去訓練棋力模型 | 只評估，不訓練 |
| 服務哪個比賽 | 棋力 | 玩家辨識（B1 的真實資料關卡） |
| 族群問題 | 致命：高活躍候選人不像棋力測試族群 | 不受影響：辨識的測試對象本來就是這種候選人 |
| 規則 | 跨比賽使用作廢測試資料，要先問 | 只用玩家辨識自己的資料；不碰棋力測試，不做跨比賽辨識 |

棋力 session 對 A1、A2、B2 的判斷我們同意，都不做。

## 3. 步驟（依序；前一步不過就停）

**步驟 0：上限診斷（CPU，棋力 session 也同意先做）。** 在模擬題池（訓練資料，真實等級已知）裡，看新主線不配對時剩下的錯題（約 24 題／4,000）有幾題是「挑到不同等級的人」，再加一個「完美棋力成分」（用真實等級）算出增益上限。如果大多是同等級互相認錯，B1 到此為止。

**步驟 1：逐局 L1 打分（GPU，棋力 session 的 trunk_seq／l1b 流程）。** 範圍：舊 Public 候選人 40,000 局，加題目 5,000 局，共約 4.5 萬局，全部執黑；以及步驟 2 模擬題池所需的訓練局。

**步驟 2：10 維機率。** 照 `m60_colour_pure_cv.py` 的流程：
- 候選人 100 局切成 5 組 × 20 局，各自預測後把 log 機率平均；題目直接用原本的 n 局。
- 官方玩家不在訓練集，用 4 個 fold 的 ct9 成員取平均；模擬題池裡的玩家用避開他所在 fold 的成員（val{v}）。

**步驟 3：B1 成分（事先固定，不調）。**
- 每題、每位候選人的分數 = 10 維 log 機率向量的 cosine。向量先在 400 位候選人之間逐維標準化。
- 不轉成類別、不校準。棋力 session 指出模型殘差有穩定的玩家層地板，對辨識來說這個偏差本身就是訊號。

**步驟 4：真實資料關卡（Public 400 題，答案確定）。**
- 主指標：B1 單獨的官方分數（Top-5，e^-(r-1)），以及真答案在 400 人中的名次中位數。亂配基線 = 1.571 / 400 = 0.0039。
- 判定：B1 單獨分數至少達到同一指標在模擬題池上的 80%（表示訊號在真實官方資料上沒有掉），才進入步驟 5。
- 只報告、不作決定：加進融合後，Public 不配對時的 2 題錯題有沒有被修正（題數太少，檢定力很低）。

**步驟 5：採用決定。** 照本案慣例：一題一人的最終 CV（含配對與不配對兩種情境），事先指定「新主線＋B1」對「新主線」，用玩家 bootstrap；兩組 fold 同號，且整體 ≥ +0.003 或 n=5 ≥ +0.005。

**附帶報告（給棋力 session 參考，不作任何決定）：**
- 同一人 5 組 20 局的預測類別一致率。
- n 局題目和 100 局共識的一致率，按 n 分開。
- 限制：族群是高活躍玩家，不代表棋力測試族群，只能當作模型在官方資料上的穩定度參考；不一致也可能是那個人真的進步了，因為候選局和題目局可能來自不同時期。

## 4. 成本

- 步驟 0：只要 CPU，約 1 小時。
- 步驟 1：GPU。舊 Public 4.5 萬局約 1 小時（8 卡）；模擬題池的訓練局看題池大小另計。
- 步驟 2–4：主要是 CPU，GPU 只用來跑 ct9 推論。

## 5. 規則立場

- 只用玩家辨識比賽自己的資料，符合 README「僅供 2026 AI CUP 競賽使用」。
- Public 答案只用於評估，不用於訓練，和 METHOD_NOTES §2.23 不拿反推答案訓練嵌入的立場一致。
- 不使用棋力測試資料，也不做任何跨比賽的玩家辨識。
